# Sums, `/sums`

Maths practice for Sam's two daughters, written by finger or stylus on a touch screen. Built 2026-11-15. Handwriting is read **on the device** by a small neural network: no API, no network calls, works offline once loaded. Not linked from any index; `noindex`. A plain-English project note for Sam is in the Obsidian vault at `Projects/Sums/Sums.md` (update it when the plan changes).

**Users.** A 5-year-old in US-style kindergarten who **can't read yet** (pictures, numbers and spoken prompts only, never written questions she must read) and a nearly-8-year-old in grade 2 working above level (she found the first age-8 set straightforward). Sam wants them free to explore: the girls change their own settings, nothing is locked.

**Organised by NZ curriculum year.** `CURRICULUM.md` lists the NZ Years 0–6 maths curriculum (October 2025 teaching sequences, re-checked against the PDFs 2026-11-16) with each Sums activity ticked against it, and "Out of step" notes where a game does something in a different year ("quarter to" in Year 2, long division before Year 5). `NZC Maths Activity Alignment.md` is Sam's outside audit with ideas for new activities (Sam's file, untracked). Sam wants skills both **across** (everything for her year) and **down** (one skill through the years), and never to drop an activity because she has moved up. New activities are built "vertically": one activity with a **Year** option for each level (Years 1–4 for every year activity so far).

**Before committing:** run `test/run.sh` (all must pass; questions are random, so run it twice after layout changes). Update `tracker/projects.md` and run `python3 tracker/publish.py` (see the repo CLAUDE.md).

**Sam's look rules.** The sheet stays plain, like a paper printout (he likes it). Pictures are very clean and simple; block colours only where they add value (graph categories as colours a non-reader can match, a flat colour on a shape), never just for prettiness. The front screens can be more designed than the sheet. Not AESTHETIC.md.

## Review page, links and problem reports (2026-11-17)
- **`/sums/review/`** (`review/index.html`): Sam's "To check" list as cards: what to check in a line, and buttons that open Sums at that activity with the right choices. Ticks are per device (localStorage `sums-review`), ticked items fold into "Checked". The list is the `ITEMS` array (plus `OPEN` for the open problem) and **must match the "To check (review later)" list in the vault note**: every build step adds its lines to both (step 7 of "How to run a step").
- **Links into Sums**: `../?act=<act>&yr=4&kinds=a,b&n=12` (any option key of that activity, plus `n`). `LINK` is read at load; the names screen says "Next: Rulers, Year 4. Pick who is trying it."; after a name (Everyone with a `yr` skips the year question and is in that year; the home page is set to it too) `goHome` hands over to `openLink`, which opens the setup with those choices in the draft (not saved until Start) and clears the address. Unknown keys and values are ignored. `setup: 'none'` activities go straight to a sheet. Tests check every review link.
- **Report a problem** (`report.js`, loaded by `index.html`, `mock/` and `review/`): a small flag button at the end of the `<header>` opens a panel (reason chips, optional words, Send) that POSTs to the shared unisam-feedback Worker as app `sums`, like Grill. `window.sumsReportContext` (in `index.html`) adds JSON as `diagram`: screen, age, activity, settings, and on a sheet every card's `q`, state, what was read, tries and her strokes (rounded, em units), or the grid state. **Never the player's name.** On phones (≤ 600 px) the flag is hidden on sheets and the grid because the header is full; tablets show it.

## Flow
1. **Names** (opening screen): big name tiles, Everyone, "+ Add a name". Switching names clears the current sheet or grid, so nobody lands on someone else's.
2. **Year** (2026-11-17, was age; Sam: "don't refer to it by ages"): "What year are you in?" with tiles **Year 0 to 8** (`YEARS`), read aloud. A named player is asked once; the year is saved on the player as `{ year, yy }` (`yy` = the calendar year it is for). **Every 1 January everyone goes up a year** (`rollYears`, run on page load: `year += thisYear − yy`, capped at 13). Players saved with an `age` become `year = age − 4` (0–8) on load and lose the age. **Everyone** is asked every time (its settings are stored per year: `sums-cfg-guest-y<year>-<act>`). Her year decides:
   - the tile set defaults (`group()`): Years 0–2 the younger set (`defaults(5)`), Year 3 up the older (`defaults(8)`);
   - read-aloud (`reads()`): Years 0–2 (based on her year, not the page she is looking at);
   - which year page home opens on (`view`, the nearest page built).
3. **Home: one page per year** (`view`; ‹ › buttons, dots, and a sideways swipe of 60 px+ on the page; `turnPage`, `drawHome`). Pages are every year some activity has (`pageYears()`: Years 1–4 so far, new years appear by themselves). On page N (`onPage`): an activity with a Year row if it has Year N exactly; one without a Year row if it is in that page's tile set (younger for Years 1–2, older for 3 up); the original Sums everywhere. So True or false is on Years 1, 2, 4 and 5 (not 3), Arrays on 3 and 4. Beside the switcher: "your year", or "the highest so far (you're in Year 6)". Tile best times are for that page's year. Tapping a tile opens its setup with **Year = the page's year** (her other choices kept; saved only on Start). The setup's green dot and line say "Your year: Year 3" or "From the page for: Year 2" (plus "(Year 4 is the nearest/lowest/highest here so far)" when the activity lacks it). `suggestedYear` = the nearest year the activity has to `view`, a tie going down. The finish panel's **Harder** goes to the next year the activity has. Header: ‹ Names, speaker, "Name · Year N", Records. `overscroll-behavior-x: none` and `touch-action: pan-y` stop the swipe being the browser's back gesture (it was, in headless Chrome).
4. Tapping an activity **with choices opens its setup page first** (Sam: ask every time), with that player's own last choices selected; title "Name · Activity"; at 4–6 it says "Choose, then press Start." Activities with no choices (Make 10, Teen numbers) go straight to the sheet. Back on a setup returns where she came from (home, or her sheet/grid via Start again).
5. **Sheet** (cards) or **grid** (Times grid): header ‹ Home, Start again (that activity's setup), speaker (repeats the question), score, **Working**, Mark. At 4–6 the question is spoken when the sheet opens.
   - **Working area** (Sam): "Working" opens a plain page to work things out: the bottom third in portrait, the right third in landscape (the sheet shrinks to the rest). Undo, Clear, Hide. Nothing on it is read or marked; it empties with each new sheet. Open or closed is remembered on the device (`sums-working`). Strokes are in pixels, so they don't move with rotation.
   - **Finished** (Sam: there was no obvious next step after a sheet was all right): 0.7 s after the last card turns green (so she sees the ticks), a panel over the sheet (header still usable): a green tick that pops in with a small burst of block colours (none with reduced motion), "Perfect!" (all first try) or "All done!" (said aloud at 4–6), the time, first try N of M, "New best!" or the best. Buttons: **Another sheet** ("Another grid" on the grid), **Harder: Year N** (only where there is a higher year; saves it as her choice), **Choose something else** (home), and a small "Look at my sheet" that closes it. `queueDone`, `showDone`, `hideDone`.
6. **Records** page: change year (tiles, "goes up by itself every 1 January"), best times and recent sheets for every activity, each with **Delete** (Sam: for when someone else did a sheet on her name). Deleting one recent sheet works its best time and count out again from what's left; deleting a best-time row removes every sheet of that kind. **Remove** (the person: records and settings too). All deletes are double-click proof (`arm`): the first tap turns the button into Keep, the real confirm appears at the top, ignoring taps for 0.5 s.

**Scrolling**: the front screens (names, age, home, setup, records) scroll the page itself with a sticky header; sheets and the grid lock the page (`body.lock`) and the sheet scrolls inside. Sam's Firefox would not scroll the home tiles inside the old fixed panels.

## Activities (`ACTS` in index.html)
Each has `name`, `ages` (tile set: 5 younger, 8 older), `setup` kind, `say` (spoken prompt), `pic` (tile SVG), `defaults(group)`, `make(cfg)` → question (`kind` + `ans`), `key(cfg)` / `label(key)` for records; optional `options`, `blocked(cfg)` (warning text that turns Start off), `grid`, `noCount`. A question can carry its own spoken words in `q.say` (`cardSay` uses it first).

**Year options.** Written `{ key: 'yr', values: [[1, "1 · o'clock"], ...] }`; the setup page shows "Year 1" in bold on its own line and the text after " · " as the example under it (`.yrb`; Sam: "1 · o'clock" made the 1 look like part of the example).

### Younger tiles (ages 4–6) only
- **How many?**: Kind **Ten frame**: ten frame(s), dots filled in order (top row left to right). Up to 5 / 10 / 20 (20 = two frames, first full). No line under ten frames (Sam removed it); she writes anywhere below. Kind **Groups** (B1, `q.parts`, `q.cols`, `clustersSvg`): two dice patterns (1–6 each, `PIPS`), each on a thin rounded die in its own block colour, total up to 10 (or up to 5); answer is the total. Both kinds on by default. Record key `howmany~<max>|<n>` for ten frames only (as before), else `|frame,groups` or `|groups` on the end.
- **Number bonds**: whole circle on top joined to two part circles; one is empty (`.hole`) and she writes **inside it** (stroke centre within 1.9 em of the circle centre; radius 1 em). Up to 5 / 10 / 20. A part of 0 only about 1 card in 10.
- **Teen numbers**: 11–19 as a full ten frame plus a second frame with 1–9 dots.
- **Make 10**: one ten frame, 1–9 dots, empty spaces as dashed circles; answer = 10 − dots.
- **Picture patterns** (`pat`, `patQ`, `patSvg`, tap card, Years 1 and 2, B3, D2a): a row of 7 to 9 shapes (`mapThing`, `PAT_SHAPES`, `PAT_EM` sets the size) repeating a unit of three, one gap drawn as a dashed box, never in the first three (so the answer is always the shape three before it). Type shape only (one colour), colour only (one shape) or both, a third each; no Kind row. No words on the card. Tiles are the three parts (big tiles, `thingSvg`), each says its colour, shape or both when tapped (that names nothing away); the speaker reads "What is missing?" and the three tiles. Record key `pat~1|6`. **Year 2** (D2a, `pat2Q`, `q.ask`, no Kind row, key `pat~2|n`): half **Which part repeats?** (`ask: 'unit'`): units from `PAT2_UNITS` (AB, ABB, AAB, ABC, ABCB, ABAC, AABB, ABBC, ABCD; letters map to shapes / colours / both as in Year 1), a row of 2k + 2 or 3 (at most 10) with no gap; three tiles one under another (`tcls: 'prow'`, each a short row `patRowSvg`): the unit and two starts of the row that are too short or too long, or the unit with a shape added (`repeatsAs` throws out any that also repeat, e.g. ABAB); tiles say "this one", the card is `quiet` and only says "Which part repeats?". `topf` 0.27: phones (12 cards) have no height to spare for a bigger row. Half **What will the 10th one be?** (`ask: 'nth'`, `patNthSvg`): units AB, ABC, ABB, AAB; the first six numbered 1–6, "…", a dashed box with "?" and the place asked (`q.p`, 8 to 12) under it; tiles are the shapes in the unit, each spoken; read aloud "What will the 10th one be?".
- **Splat** (`splat`, `splatQ`, `splatSvg`, Years 1 and 2, B4, D1b): the total as a big numeral ("8 altogether"), then one ten frame (two above 10) of dots with one flat grey blot over some. "How many are hiding?" written anywhere below. Totals 6 to 20, half within 10. The blot is a thick round-capped stroke over the last 1 to 5 dots **of one row** in the last frame (a blot over two rows would be two blots), with a few small lobes on the outer edge; the dots beside it stay whole (the test measures every dot against the blot). So the hidden number is at most 5 and the dots she sees are always in ten-frame places. No Kind. Record key `splat~1|6`. **Year 2** (D1b, `splat2Q`, `q.blots` `[{f, r, s}]`, `q.k`, `q.showing`): totals 11 to 30 (up to three frames, drawn a bit smaller at three), two or three blots each over the same 2 to 5 dots of one row, **one blot to a frame** (two in one frame touch), never a bottom-row blot over a top-row blot in the next frame (their lobes meet in the gap); the caption adds "**16** showing" on a second line; read aloud "24 altogether. 16 showing. The same number under each blot. How many under one?".
- **Halves and quarters** (`parts`, `partsQ`, `shareQ`, `cutSvg`, `cutParts`, Years 1 and 2, B4, D2b). **Year 2** (D2b, no new Kind: `partsQ(2)` and `shareQ(2)` mix in the new questions). Which one? is 40% "Which one shows a third?" too (`cutParts` has unequal thirds: strips 0.4 / 0.65 / 0.95 of the half-width; a circle is never given thirds), 30% **Which one is the same?** (`sameFracQ`, form `same`: one shape with 1/2 or 2/4 coloured beside the words, like Nets; tiles the same shape with 2/4 or 1/2 and two of 1/4, 3/4, 1/3; `quiet`) and 30% **Which coloured part is biggest / smallest?** (`biggerFracQ`, form `bigger`: one shape cut into halves, thirds and quarters as strips the same way, one part coloured each; tiles say "a half" etc.). `fracCut(shape, n, a, strips)` cuts equal parts in order round the middle (or along the strips) so coloured parts sit together; `fracPicSvg(ps, k, col, em)` colours the first k. Half of a number Year 2: "A third of 12" (three groups in a row, `SHARE_WORD`) and half the time the whole from a part (`q.whole`: "Half is 5." / "Altogether?", one group of dots, the other groups dashed boxes with "?", `rect.hid`; answers to 20). Year 1: Kind **Which one?** (tap): "Which one shows a half?" / "a quarter?" over three shapes (circle, square, rectangle, one each), one cut into 2 or 4 equal parts with one shaded; the other two are cut unequally (a share of at least 1.5 to 1) or into a different number of equal parts (2, 3 or 4; thirds only on square and rectangle). Parts are polygons made by cutting a convex outline with lines (`cutPoly`), so area is measured, not assumed. Tiles say "this one". Kind **Half of a number** (written, `share`): "Half of 8" / "A quarter of 12" as dots in 2 or 4 groups with a dashed sharing line (rows of five), halves to 20, quarters of 4, 8, 12, 16, 20. Key `parts~1|tap,write|6`.
- **Read aloud**: at 4–6 every card has a speaker in its foot (`cardSay`: "3 plus 4", "3 and 4 make what?", "7 is 3 and what?"; frames use the activity's prompt).

### Older tiles (ages 7–11) only
(True or false, More or less and Balance are listed here but are on both tile sets since B2: `ages: [5, 8]`, the younger default Year 1 with 6 questions.)
- **Missing number**: `7 + ☐ = 12` with "☐ = ___" underneath. Hides the first or second number; never an equation where any number works (0 × ☐ = 0, 0 ÷ ☐). The line length comes from the longest number shown, so it gives no hint. Keypad setup.
- **Arrays**: r rows × c columns of dots, write the total. `grid` setup: the two keypads relabelled Rows / Columns, signs and "bigger" hidden; only 0 chosen → warning, Start off. Default rows 2–5, columns 2–9.
- **Place value**: (Up to 999,999 since C1: expanded form, sometimes shuffled, and 1,000 / 10,000 / 100,000 more or less; no blocks at that size, so Blocks alone is `blocked` and Blocks with others is skipped.) Kinds Blocks (base-ten, true proportions: hundreds squares 3 a row, tens sticks, ones cubes 3 a row; `PV_EM` sets the size), 300 + 40 + 7 (zero parts left out, shuffled about a third of the time so she can't just copy digits), 10 more / 10 less (amounts 1, 10, 100, and 1,000 at 9,999; never below 0 or above the max). Up to 99, 999 or 9,999. At 9,999 the thousands are cubes (3 a row, front face a hundred square) with the hundreds beside them and the tens and ones on a row underneath, so the picture stays about square (`pvLayout(h, t, o, k)`; `q.k` is the thousands).
- **Number lines**: 10 steps, only the two ends labelled, an arrow at tick 1–9; she works out the step. Counting in 1s / 2s / 5s / 10s / 25s / 50s / 100s / 1000s; the line never goes past 10,000. The SVG has room for a five-digit label at each end.
- **True or false** (`tf`, `tfQ`, tap card): a number sentence, tiles ✓ and ✗ (spoken "true" and "not true"), about half true. **Year 1** (`tf1Q`): one-digit + and − within 10, from `oneDigitEx(v)`; a sum on the left and a number on the right, sometimes the other way (8 = 3 + 4), or a sum on both sides (7 − 5 = 6 − 4); wrong ones are out by 1. About half the cards put each side over its dots (`sideDotsSvg`: in pairs, a gap between the two parts of a sum, taken-away dots hollow with a slash; `q.dots`, `.tfd` / `.tfc`, `topf` 0.55). Year 4: four-digit + and −, tables to 12 × 10, × 10 and ÷ 10, and both-sides sentences (6 × 4 = 12 × 2, 36 + 32 = 34 + 33). False ones are near misses: out by 1, 10 or 100, two digits swapped, a times-table neighbour, or a place out. Read aloud "8205 take away 4721 equals 3484. True?". **Year 2** (D1a, `tf2Q`, `q.type` `cmp` / `tables`): half compare two numbers to 120 with < or > (`near120()`: digits swapped 16 / 61, a ten or a one apart, a hundred and its ones 104 / 14, or any two; never equal; spoken "is less than"), half the 2, 5 and 10 tables: repeated adding against times (2 + 2 + 2 = 3 × 2; wrong ones one copy too many or few) or a plain fact (5 × 4 = 25; wrong ones a table neighbour); over 18 characters it goes on two lines, breaking before "=". **Year 5** (C2a, `tf5Q`, `q.type`, `q.sign`): six-digit + and − against a number (`calc`), both sides to work out (`sum`: halve one and double the other, 2456 × 2 = 1228 × 4, or give and take, 4500 + 2700 = 4700 + 2500), decimals to two places (`dec`: 0.12 > 0.2, 0.5 = 0.50 / 0.05), decimal sums (`decsum`: wrong ones a place out, 0.4 + 0.25 = 0.29, or 0.1 / 0.01 out) and fractions where one bottom number is a multiple of the other (`frac`: 2/3 = 6/9, 2/3 > 5/9). Decimals and fractions use < or > on about 60% of their cards (`SIGN_WORD`: "is less than"). Sentences over 18 characters go on two lines, breaking before the sign; fraction and two-line cards use `topf` 0.55. Shared with More or less: `pair5(kind, same)` makes two sides `{ t, h, s, v: [top, bottom] }` (`S5`, `D5`, `F5`, `cmpV` compares exactly).
- **More or less** (`cmp`, `cmpQ`, tap card). **Year 1** (`cmp1Q`, no < > signs): "Which has more?" / "Which has fewer?" over two heaps of 1–10 dots (`heapSvg`: scattered on a 4 × 4 grid with a wobble), or "Which is more?" / "less?" over two numbers to 20 (often close, sometimes a teen and its ones digit, 14 and 4). Tiles are the left heap (or number), **same** (`SAME_TILE`, spoken "the same"), the right one; about one in five the same. Heap tiles say "this one" when tapped and the speaker reads only `q.say` (`q.quiet`), so the count is never read out. Heap cards use bigger tiles (`q.big` → class `bigt`, up to 128 px, words in the top 30%). Kinds **Dots (Year 1)**, Numbers, **Sums (Year 4)**, **Fractions (Year 4)**: a year uses only its own kinds (none left → dots / numbers), and the record key keeps only those (`cmp~1|dots,num|6`, Year 4 keys unchanged). Year 4: two sides with an empty box between them, tiles < = >. Kind Numbers (to 10,000, often the same digits in a different order, or one place apart), Sums (two close times-table facts, or thousands and hundreds: 3000 + 400 ☐ 3500 − 100); about one in five equal. Kind **Fractions** (`cmpFracQ`, printed top over bottom with `.fr`): same bottom number (3/8 ☐ 5/8, to twelfths), same top number (1/3 ☐ 1/5, mostly unit fractions), or tenths against a decimal (3/10 ☐ 0.5, 1/2 ☐ 0.5); only the decimal ones can be equal (about one in eight overall). Read aloud "3 over 8, and 5 over 8". **Year 2** (D1a, `cmp2Q`): two numbers to 120 from `near120()` (about one in five the same) with the < = > tiles; numbers only, so the Kind row is ignored and the key is `cmp~2|num|n`. **Year 5** (C2a, `cmp5Q`, `pair5`): Numbers are six digits (same digits moved, or one place apart), Sums are halve-and-double products or give-and-take hundreds, new Kind **Decimals (Year 5)** (0.12 ☐ 0.2, 1.07 ☐ 1.7, 0.2 ☐ 0.20), Fractions with one bottom a multiple of the other (any can be equal); about one in five equal. The Kind row lists Decimals; Year 4 ignores it and its record key leaves it out (`cmp~5|num,sum,dec,frac|12`).
- **Fractions of a number** (`fof`, `fofQ`, `fofSvg`, frame card, Years 4 and 5): the bar model. **Year 5** (C2b): non-unit fractions in lowest terms, d 3–10 (`q.n`): "2/5 of 150" puts a second brace under the first n boxes holding "?", "2/5 of the set is 8" puts the part under it and "?" on the top brace; Kind **Percent (Year 5)** (`q.pct`, `FOF_KINDS`): 10% (10 boxes, always find the part), 25% (4), 50% (2), "25% of 80" or "25% of the set is 7". Year 4 ignores Percent and leaves `pct` out of its key; the default kinds include it. Read aloud "What is 2 fifths of 150?", "25 percent of a set is 7. How many in the set?". Year 4: Caption "1/4 of 28" or "1/4 of the set is 7" (stacked fraction), a brace over a bar of d equal boxes. Kind **Find the part** (the whole on the brace, "?" in the first box) or **Find the whole** (the number in the first box, "?" on the brace). Unit fractions 1/2 to 1/10; the part is 2–10 (tables) or, about 3 in 10, a round number (1/3 of 300), whole at most 1,000; boxes from 6 parts up hold two digits at most. Answer anywhere under the bar. Read aloud "What is a quarter of 28?", "An eighth of a set is 7. How many in the set?".
- **Balance** (`bal`, `balQ`): an equation with one box, then "☐ = ___" (laid out like Number patterns). **Year 1** (`bal1Q`): one-digit + and − on both sides (2 + 5 = 3 + ☐, 7 − ☐ = 4 + 1), each side 2 to 10, the box any of the four numbers, never the same number on both sides; drawn over a level see-saw (`q.saw`: a plank as wide as the equation on a black triangle, `.saw`). **Year 2** (D1a, `bal2Q`, also on the see-saw): + or − on both sides with close numbers (18 + ☐ = 17 + 6, 15 − ☐ = 14 − 3; the box any of the four) and the 2, 5, 10 tables against a number (☐ × 5 = 20, 6 ÷ ☐ = 2, the box on the side with the sign); numbers 1 to 100. Year 4: four-digit + and − with a plain number on one side (4200 − ☐ = 4001), × 10 / ÷ 10 and table facts (☐ ÷ 10 = 12, 7 × ☐ = 56), and both sides to work out (36 + 17 = ☐ + 20, 6 × 8 = ☐ × 4, 64 − 25 = ☐ − 30, 250 + ☐ = 300 + 75); the box can be any of the four numbers; never the same number on both sides; sides swap half the time. Whole numbers 1 to 9,999, exactly one answer. Read aloud "36 plus 17 is the same as what plus 20?". **Year 5** (C2a): six-digit place changes (999999 − ☐ = 899999, one digit of a six-digit number moves; half the cards), × and ÷ by 10, 100, 1,000 (☐ × 100 = 4500, 36000 ÷ ☐ = 360), thousands both sides (45000 + 27000 = ☐ + 30000), tables with tens (60 × 80 = ☐ × 40); whole numbers to 999,999. An equation over 20 characters prints on two lines, breaking after "=".
- **Decimals** (`decQ`, `dec` card, Year 4 only so far: tenths): Kinds **Picture** (`decBarsSvg`: full bars of ten are ones, then one bar with some tenths shaded, 0.1 to 2.9, always in the room of three bars; about one in four is instead the fraction link "3/10 =" or "1/2 =" as a stacked fraction), **Number line** (`decLineSvg`: 0 to 2 in tenths, only 0, 1, 2 labelled, halves a bit longer, an arrow, never on a whole number), **Add and take away** (1.3 + 0.2, 2.5 − 0.4, a third cross a whole; never a whole answer), **× and ÷ by 10** (23 ÷ 10 → two blanks; 2.3 × 10 → a plain `expr` card with one line). Values are kept in tenths (`q.v`, 13 = 1.3) so nothing is a float. **Year 5** (C2b, `dec5Q`, `hTwo`, `dstr`): hundredths, values in hundredths, every two-blank card `dp: 2`. Picture: a hundred square shaded a column of ten at a time (`decGridSvg`, room of two squares; 1.xx shows a full one beside it), a quarter of cards the fraction link (1/4, 3/4, 1/2, n/100). Number line: `form: 'hline'`, `decHLineSvg`, one tenth (`q.lo`) cut into ten hundredths, both ends labelled. Add and take away to two places, about a third a tenth with a hundredth; never a whole answer. × and ÷ by 10 and 100 (N ÷ 10, N ÷ 100, 0.47 × 10 two blanks, 0.4 × 100 a plain `expr` card). Kind labels are shared; the record label says "× ÷ 10, 100" for Year 5.
- **Rounding** (`roundQ`, Years 2, 4, 5): nearest 10, 100, 1,000 (numbers to 9,999) or tenths to the nearest whole number. Kind **Number line** (`rline`, `rlineSvg`: a 10-step line between the two candidates, both ends labelled, the number on an arrow at its place; "to the nearest 100" above; answer below; never exactly halfway) or **Just numbers** (`rnum`: the number big, "to the nearest 100" under it, then a line; halfway allowed, rounds up). A number already round is never asked. Answers can be 0 (0.3) or 10000 (9960). **Year 2** (D1b): nearest 10 for 11 to 119; on both tile sets since D1b (`ages: [5, 8]`), the younger default is Year 2, Number line only, 6 questions. **Year 5** (C2a, `round5Q`): six digits to the nearest 1,000, 10,000 or 100,000 (never rounding up to a million), tenths or hundredths (0.01 to 99.99) to the whole number, dollars and cents ($1.01 to $99.99) to the nearest dollar (`q.pre = '$'`: printed before the line in Just numbers and on the line's end labels). `rlineSvg` widens itself for six-digit labels.

## The sheet (plain, like a paper printout; Sam likes it, keep it that way)
- Grid of cards follows rotation: portrait 2/3/4 columns for 6/12/20, landscape 3/4/5, phones in portrait always 2 (scrolls).
- `qMarkup(q)` prints each question; `--h` / `--c` (height and width in em) set the font size to fit the card. Layouts: `col` (stacked + − ×: carry space on top, sign left, line under), `div` (long-division bracket, answer on the bar), `miss` (a line of text, then "= ___"; also `expr`, `seq`, `bal` and `rnum` cards), `story` (wrapped words, then "___ unit"), `bond`, `frac`, `pic2` (clocks, money, graphs, shapes, rulers: question or picture, then blanks; `qMarkup` can name its own `anchor`; a `<br>` in a graph caption gives it two lines), `tap` (see below), and `frame` (any picture on top, answer anywhere below: ten frames, arrays, blocks, number lines, rounding lines, area, Year 1 doubles).
- Each card is one writing surface (`.work`, canvas over the printed question). Strokes are stored relative to an **anchor** in units of the printed font size, so writing stays lined up after rotation: `.rule` (col), `.dd` top (div), `.wl` (miss/expr/seq/story), centre of `.hole` (bond), `.fbar` (frac), `.ln` (single blank on pic2), the middle of ":" or "and" on the lines (two blanks), bottom of the picture (frame). The anchor and font size are **measured again at every pen-down** (`remeasure`; earlier strokes stay where she wrote them).
- **Which writing is the answer** (`answerStrokes` + `inZone`): below the line (col, frame), above the bar (div), inside the empty circle (bond), everything (miss/expr/seq/bal/rnum/story/pic2, so an answer on the line, in the box or a bit low all count), above/below the bar (frac). Ruled lines she draws are ignored; several rows → the bottom row. If a card has writing but none in its answer place, all her writing is read instead of skipping the card.
- **Two blanks** (`q.two`, `q.parts`): Clocks Year 2 up, Money Year 3 up, and Decimals (a printed point, `q.dp` = decimal places). Shown as "3:05", "$2 and 50c" or "1.3". Decimals: after the point digits keep their places (1.03 is not 1.3) but trailing zeros are forgiven (1.30); an empty first blank counts as 0 (".7"); if both numbers land on one side, the last `dp` digits are the decimal part. `twoParts` is forgiving (Sam found writing missed): strokes are grouped into digits (`digitClusters`) and each digit goes left or right of the middle; dots (her own colon or point, under 0.3 em) are not digits; writing more than 2.4 em up (on the clock or coins) is ignored unless it lines up with a digit below; if both numbers land on one side it splits by her own colon or point, else the last two digits are the minutes / cents; it never ignores all her writing. Money drops a "$" (taller than her digits) before and a "c" (smaller) after (`dropMoneySigns`), on single blanks too.
- `readAnswer(c)` reads and checks every card (`{ text, ok, backwards }`); fractions compare n·D = N·d. A reading error shows on the card as "? (Error: ...)" instead of nothing (`safeRead`; Mark skips that card).
- After a 0.5 s pause the reading shows in big grey text (26 px, Sam) under the card.
- **Mark marks every card with anything written on it, in one press** (Sam): 4 of 12 done → those 4 marked, clock keeps going; the sheet finishes when all are right.
- **Wrong** (Sam): only "Try again" (clears the answer, keeps working); the answer is never shown. When a later try is right, the card shows "first read N" and **I was right the first time**, which counts it as first try right (and updates the saved history if the sheet is already finished).
- **Backwards digits**: the reader has 17 classes, 0–9 plus BACKWARDS 2 3 4 5 6 7 9, because a flip check can't tell a backwards 5 from a real 2 (tested: same confidence). A backwards digit still counts; the card shows it mirrored next to the right way round, and at 4–6 it is said ("Watch out, your 3 is backwards"). Sam briefly floated a "receptive" version (choose which way round is right) and dropped it.
- Palm rejection once a stylus is used (cards and the working area). Undo removes the last stroke.
- **Tap cards** (`kind: 'tap'`, built in A2): `{ top (html), tc / th (its width and height in em), tiles: [{ html, label, say }], right (index, or indices with multi), say }`, optional `multi` and `cells` (tiles as a grid, `cells` across). The card gets class `tapc`: no canvas, Undo or Clear, the `.qv` takes clicks. Tile size comes from the card, not the font (`--tw` from `cqh`/`cqw`, 40–84 px, cells 30–60 px), so every card on a sheet has the same big tiles; the words keep to the top 45% (30% over a grid). A tap picks a tile (`c.pick`, thick inset border, `paintTap`), another tap moves it (multi: on and off); it starts the clock. At 4–6 a tapped tile says its `say`, and the card speaker reads `q.say` then every tile. `readAnswer` gives the chosen labels and `ok` (multi: all and only the right ones). Mark leaves the reading blank (the tile shows it); wrong is the red border and Try again, which clears the choice; no "I was right the first time". The Working area works as usual. `writeNum` in the tests just picks the right tiles. **`q.axes`** (Map): a label span before each grid row and a row of letters under it (`.ax`, half a tile), the grid allowed 72% of the card height. **`q.tray`** (Make it): a `.tray` box between the question and the tiles; taps add to it rather than choosing; the speaker reads only `q.say` for grids and trays.
- Look: black and white; the only colour is dark green / dark red card borders, grey fraction shading, and block colours in the Graphs, Shapes, Rulers and Money pictures.

- `CURRICULUM.md`: NZ Years 0–6 maths curriculum with what Sums covers.
- `mock/`: the big-grid mock (see above).
- `digits.js`: the reader. `readNumber(strokes, unit)` splits strokes into digits (x-overlap grouping, or a thin stroke inside a wider one such as a 4's down stroke), renders each MNIST-style (20 px box, centre of mass at 14,14, stroke radius 1.25 px), runs the CNN in plain JS, and returns `{ text, digits, backwards }`.
- `model.js`: int8 weights (~80 KB). CNN conv16/conv32/conv64 (3×3, relu, maxpool) → fc64 → fc17. `digits.js` reads the class count from the weights, so a 10-class model still works.
- `train/train.py`: retrains on MNIST with augmentation, mirroring a quarter of each batch into the backwards classes. Needs torch (`pip install --target <dir> torch --index-url https://download.pytorch.org/whl/cpu`, run with `PYTHONPATH=<dir>`) and the MNIST .gz files in `train/mnist/` (gitignored). `python3 train.py <out.js>` (~10 min on CPU). Last run (2026-11-15): 99.2% digits, 98.3% backwards digits. `train/tojson.py ../test/mnist_sample.json` makes the parity sample (gitignored).
- `test/run.sh`: node reader tests (synthetic pen strokes, backwards digits, splitting, JS = PyTorch parity), then headless-Chrome tests of every screen and activity (speech stubbed and checked). `SUMS_SHOTS=<dir>` saves screenshots.
- **Firefox** (Sam's browser) can be driven by the same puppeteer-core: `puppeteer.launch({ browser: 'firefox', executablePath: '/usr/lib/firefox/firefox', headless: true })` (not `/usr/bin/firefox`, a shell wrapper). Touch works with `hasTouch` + `page.touchscreen` in both browsers.
