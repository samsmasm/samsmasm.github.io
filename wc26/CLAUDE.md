# CLAUDE.md — World Cup 2026 Sweepstake

## What this is

Office World Cup 2026 sweepstake leaderboard. 41 players each picked teams; points scored as results come in. Pure static site, scored client-side from ESPN's free API.

Live at: `unisam.nz/wc26/` (auth-gated via Cloudflare Worker `wc26-auth`).

## Architecture

### ESPN API (CORS-open, no key needed)

- Scoreboard: `site.api.espn.com/apis/site/v2/sports/soccer/fifa.world/scoreboard?dates=YYYYMMDD-YYYYMMDD`
- Standings: `/apis/v2/.../standings` (group tables)
- Fetched in date-window chunks across the tournament. 3-min localStorage cache.

### wc-core.js — shared utilities (critical)

**Must load before app.js and schedule.js.** Both files destructure `window.WC` at top level.

Key exports: `WC.orient(a, b, matchRecord)`, `WC.outcome()`, `WC.isPlaceholderTeam(name)`, `WC.canon()`, `WC.same()`, `WC.pairKey()`, `WC.buildMatchMap()`.

**Never read an ESPN score field directly.** Always use `WC.orient(a, b, match)` — ESPN sometimes lists teams in reverse order to how a fixture was predicted, so orientation must be corrected per call.

### Scoring

- Group match: 1pt; group winner bonus: 2pt
- One chosen group doubles its group-stage points only (`data.js` has `doubleGroup` per player)
- Knockout: R32 1pt / R16 1pt / QF 2pt / SF 3pt / Final 4pt per correct team
- 3rd-place playoff: 5pt; champion: 10pt
- Final score is tiebreaker only, then alphabetical

**R32 is gated** to end of group stage — do not award R32 points from provisional ESPN "advance" flags.

## Critical gotchas (each cost a wrong commit)

### 1. ESPN standings not in rank order
`entries` array in standings is NOT sorted by rank. Always pick the entry whose `rank` stat equals 1. Never take `entries[0]`.

### 2. Placeholder teams in bracket
ESPN publishes future knockout fixtures early with placeholder names: `"Group I Winner"`, `"Third Place Group A/B/C/D/F"`, abbrs `1I`/`2J`/`3RD`, etc. `WC.isPlaceholderTeam(name)` filters these. A round is only `resolved` once its real-team set reaches full size (`ROUND_FULL` = r32:32, r16:16, qf:8, sf:4, final:2).

### 3. ESPN standings "advance" flag over-counts R32
ESPN tags all 12 third-placed teams as candidates even though only 8 qualify. Derive R32 membership from published bracket fixtures only, not from the advance flags.

### 4. orient() — team order in fixtures
Matches are stored under a sorted-pair key. Any read of a score MUST be re-oriented to the caller's team order via `WC.orient(a, b, matchRecord)`. Symptom: a team won 4-1 but nobody scored for picking them because the fixture stored the teams in reverse.

### 5. Team name normalisation
ESPN uses non-standard names. Always go through `WC.canon()` / `WC.same()`. Known variants: `Korea Republic`/`South Korea`, `Türkiye`, `Curaçao`.
